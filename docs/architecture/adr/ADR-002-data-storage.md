# ADR-002: Зберігання та обмін даними

- **Статус:** прийнято, 19.11.2026
- **Контекст:** невеликий список завдань одного користувача; зв’язок Subject 1:N Task; збереження після оновлення сторінки (NFR-02); без сервера (NFR-03).
- **Рішення:** масив Task у localStorage одним JSON під ключем `studyplanner.tasks.v1`; доступ лише через Storage Adapter (try/catch, перевірка схеми). Мережевий обмін — лише завантаження статичних файлів по HTTPS. Перехід на v2 (created_at, completed_at, Subject) — через міграцію.
- **Альтернативи:** IndexedDB; backend з PostgreSQL/SQLite; експорт/імпорт файлу як основний механізм.
- **Наслідки:** (+) простота, офлайн, немає ПД поза пристроєм; (–) ліміт ≈ 5 МБ, немає синхронізації, дані зникають при очищенні браузера; цілісність забезпечується кодом, а не БД.
- **Умови перегляду:** потреба в синхронізації, Google Calendar або великий обсяг даних — серверне сховище (новий ADR).
