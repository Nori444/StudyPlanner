## DEF-01: Завдання зникають, коли зміни роблять у двох вкладках (втрата даних)
- **Severity / Priority:** Critical / High. Critical за матрицею (втрата даних). High: блокує вихідний критерій «немає відкритих Critical». Ризик R8 був прийнятий у ЛБ4, але тест показав реальний вплив.
- **Вимога / ризик:** SP-13, ризик R8; тест-кейс TC-16
- **Повторюваність:** Завжди
- **Кроки:**
  1. Відкрити `src/index.html` у вкладках A і B (порожній список).
  2. У A додати «Із вкладки A».
  3. У B (без перезавантаження) додати «Із вкладки B».
  4. Перезавантажити A.
- **Очікувано:** У списку обидва завдання.
- **Фактично:** Є лише «Із вкладки B»; завдання з A втрачено.
- **Першопричина:** `commit()` записував у localStorage застарілу копію списку з пам’яті вкладки.
- **Виправлення:** `fix/DEF-01-two-tabs-data-loss`: читання свіжого стану перед записом і подія `storage`.
- **Доказ:** `docs/lb6/evidence/baseline/TC-16_fail.png` → `docs/lb6/evidence/after/TC-16_pass.png`
- **Retest:** Pass (e2e `lb6.js`, TC-16); **Regression:** unit 30/30, smoke 23/23, e2e LB6 9/9 — Pass
- **Статус:** Closed (Verified) 20.11.2026

## DEF-02: Дата з 5-значним роком мовчки відкидається: завдання зберігається «Без дедлайну»
- **Severity / Priority:** Major / High. Major: ключове поле втрачається без повідомлення, є обхідний шлях. High: тиха відмова на головній формі, виправлення мале.
- **Вимога / ризик:** SP-04, ризик R5; тест-кейс TC-15
- **Повторюваність:** Завжди
- **Кроки:**
  1. Ввести назву «Реферат».
  2. У полі дати набрати рік із 5 цифр (12345-01-01; Chrome це дозволяє).
  3. Натиснути «Додати завдання».
- **Очікувано:** Повідомлення біля поля дати; завдання з хибними даними не додається.
- **Фактично:** Завдання додано з «Без дедлайну», помилки немає.
- **Першопричина:** `createTask()` підставляв `due=""` для дати, що не пройшла календарну перевірку.
- **Виправлення:** `fix/DEF-02-invalid-date-silently-dropped`: `validateDue()` і `#due-error`.
- **Доказ:** `docs/lb6/evidence/baseline/TC-15_fail.png` → `docs/lb6/evidence/after/TC-15_pass.png`
- **Retest:** Pass (e2e `lb6.js`, TC-15); **Regression:** unit 30/30, smoke 23/23, e2e LB6 9/9 — Pass
- **Статус:** Closed (Verified) 20.11.2026

## DEF-03: Назва з емодзі: довжина рахується в UTF-16, 60 емодзі відхиляються («зараз 120»)
- **Severity / Priority:** Minor / Medium. Minor: обмежений вплив, є обхідний шлях. Medium: емодзі в назвах студентських завдань поширені.
- **Вимога / ризик:** SP-11; тест-кейс TC-14
- **Повторюваність:** Завжди
- **Кроки:**
  1. Ввести назву з 60 емодзі «😀».
  2. Натиснути «Додати завдання».
- **Очікувано:** Приймається (60 ≤ 100).
- **Фактично:** Відхилено: «…від 1 до 100 символів (зараз 120)».
- **Першопричина:** `String.length` рахує UTF-16 одиниці.
- **Виправлення:** `fix/DEF-03-title-length-graphemes`: `charLength()` (графеми, запасний варіант — кодові точки).
- **Доказ:** `docs/lb6/evidence/baseline/TC-14_fail.png` → `docs/lb6/evidence/after/TC-14_pass.png`
- **Retest:** Pass (e2e `lb6.js`, TC-14); **Regression:** unit 30/30, smoke 23/23, e2e LB6 9/9 — Pass
- **Статус:** Closed (Verified) 20.11.2026

## DEF-05: Storage Adapter приймає записи, що порушують правила (назва 5000 символів, порожня назва, дедлайн «не дата»)
- **Severity / Priority:** Minor / Low. Minor: потрібне навмисне редагування localStorage, дані не витікають. Low: захист у глибину.
- **Вимога / ризик:** SP-09, ризик R2; тест-кейс TC-17
- **Повторюваність:** Завжди (потрібне ручне редагування сховища)
- **Кроки:**
  1. У DevTools записати в `studyplanner.tasks.v1` завдання з `due:"не дата"` або назвою 5000 символів.
  2. Оновити сторінку.
- **Очікувано:** Дані вважаються пошкодженими: банер і копія в backup.
- **Фактично:** Записи показуються, у дедлайні — сире «не дата».
- **Першопричина:** `isValidTask()` перевіряв лише типи полів.
- **Виправлення:** `fix/DEF-05-storage-schema-rules`: правила Task Service застосовано в адаптері.
- **Доказ:** `docs/lb6/evidence/baseline/TC-17_fail.png` → `docs/lb6/evidence/after/TC-17_pass.png`
