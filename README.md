# StudyPlanner

## Опис проєкту
StudyPlanner — навчальний вебзастосунок для планування завдань і контролю дедлайнів студентів.

## Проблема
Студентам складно контролювати навчальні завдання, які надходять із різних джерел. Через це можна забути про важливі дедлайни.

## Мета проєкту
Створити зручний застосунок, який допомагає організовувати навчальні завдання в одному місці.

## Основний сценарій MVP
1. Студент вводить назву (1–100 символів після видалення пробілів), за бажанням предмет і дедлайн.
2. Застосунок перевіряє введене й показує зрозуміле повідомлення, якщо правило порушено.
3. Завдання з’являється у списку, дедлайн показано як `дд.мм.рррр`; невиконане завдання з минулим дедлайном має позначку «Прострочено».
4. Студент позначає завдання виконаним або видаляє його після підтвердження.
5. Після перезавантаження сторінки завдання збережені; збій або пошкодження сховища не руйнують застосунок і дають зрозуміле повідомлення.

## Можливості
- Додавання завдань із предметом і дедлайном.
- Перегляд списку, позначення виконаних.
- Видалення з підтвердженням.
- Збереження в браузері (localStorage) із перевіркою схеми й правил та резервною копією пошкоджених даних; зміни з однієї вкладки не затирають інші.

Редагування завдань поза межами MVP (див. [статут](docs/project-charter.md)).

## Цільова аудиторія
Студенти, які хочуть краще організувати свій навчальний процес.

## Запуск
Передумови: сучасний браузер (Chrome, Edge, Firefox, Safari). Сервер, збирання й залежності для запуску не потрібні.

```bash
git clone https://github.com/Nori444/StudyPlanner.git
cd StudyPlanner
# відкрийте файл src/index.html у браузері (подвійний клік або команда нижче)
xdg-open src/index.html      # Linux;  macOS: open src/index.html;  Windows: start src\index.html
```

## Конфігурація
Змінних середовища, ключів і секретів немає, файл `.env` не потрібен. Усі дані користувача лежать лише у браузері під ключем `studyplanner.tasks.v1`.

## Перевірка
Передумова: Node.js 18 або новіший (лише для тестів).

```bash
npm test                     # 30 unit-тестів (Storage Adapter, валідація, дати, лічильник)
```

Ручний smoke test (5 хвилин) описано в [docs/smoke-test.md](docs/smoke-test.md). Необов’язкові e2e-тести (Playwright): `npm i --no-save playwright && node tests/e2e/smoke.js && node tests/e2e/lb6.js`. Перевірка секретів: `bash scripts/check-secrets.sh`. Результати ЛБ7 (захист): [аудит](docs/lb7/01-readiness-audit.md), [матриця простежуваності](docs/lb7/02-traceability-matrix.md), [сценарій демо](docs/lb7/03-demo-script.md), [ретроспектива](docs/lb7/05-retrospective.md); демо-прогін `node tests/e2e/lb7-demo.js`, перевірка документів `bash scripts/check-docs.sh`. Результати ЛБ6: [тест-план](docs/test-plan.md), [результати](docs/test-cases.md), [журнал дефектів](docs/defect-log.md), [звіт](docs/test-report.md), [release notes v0.1.0](docs/release-notes-v0.1.0.md).

## Структура
| Шлях | Призначення |
|---|---|
| `src/storage.js` | Storage Adapter: єдиний доступ до localStorage, перевірка схеми, backup |
| `src/tasks.js` | Task Service: правила валідації, формат дати, «Прострочено» |
| `src/app.js` | Інтерфейс: відображення, банер помилок, підтвердження видалення |
| `tests/` | Unit-тести (`node --test`), e2e smoke і сценарії ЛБ6 |
| `docs/` | Статут, backlog, план ітерації, ризики, архітектура, тест-кейси, журнал рішень |

## Відомі обмеження
- Дані зберігаються лише в браузері й не синхронізуються між пристроями (між вкладками одного профілю — синхронізуються, DEF-01).
- Облікових записів і ролей немає, тому контроль доступу не застосовується (див. статут); дані видимі лише власнику браузерного профілю.
- Якщо один запис у сховищі пошкоджений, весь список вважається пошкодженим; сирі дані лишаються у ключі `studyplanner.tasks.v1.backup`.
- Firefox і Safari не перевірялись (TC-22); незалежного тестування не було. Повний список: [release notes](docs/release-notes-v0.1.0.md).
